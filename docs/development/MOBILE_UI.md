# 管理界面的移动端密度(移植自 xinhai-ai/Stronghold-Protocol)

本分支把**战场**和**非战场管理界面**分开处理:`.gm__hud`、商店、HUD 几何、聊天尺寸和详情卡都不动,只有管理界面走这一层,加上**一个例外** —— 作战统计面板(`.combat-metrics`,见下节的最后一小节)。
`public/css/utility-mobile.css` 在 `devices.css` **之后**加载(源码 `public/index.html`、`public/dev/*.html` 和 Vite 构建都是),除此之外没有别的样式表排它后面。

## 作用域与密度

规则在 **1000 CSS px 宽以下**或 **600 CSS px 高以下**生效。桌面布局不变,`html` 的全局 `rem` 也不变。
共享排版用 `var(--utility-text, var(--t))`;每个容器自己声明自己的文字基准。

`--utility-text` **必须由每个界面自己声明**,因为 `UiHosts` / `GuideHost` / `LoadoutHost` / `StatsHost` / `ResourceManagerHost` 都是 `.app-root` 的子节点、**不是屏幕的子节点** —— 从标题页或对局中打开的资源管理弹窗继承不到大厅上的变量。
这个变量**只允许出现在 `font-size` 上**,不能用来算宽度、高度或战场定位;`test/ui/utility-mobile.test.js` 会扫描该层每一条声明。

`ba744327` 把声明分成两类:

- **管理用表面**——`:is(.modal--utility, .guide, .lo, .st)`——保留可读下限 `max(var(--t), 64px)`,它们的字号另有显式 px 下限兜底。
- **游戏尺度表面**——`:is(.title-screen, .lobby-screen, .room-screen)` 以及资源预载 / 设置 / 关于三个弹窗(`.utility-modal.resource-modal` / `.settings-modal` / `.about-panel`)——改成 `var(--t)`,**跟战场同一文字尺度、不吃下限**。理由是下限会让手机上的 `小` 与 `中` 一样高、选择 `小` 在这些界面上完全不起作用。代价是手机上 `小` 时这些界面文字确实很小(`1rem` 被 `html` 的 `clamp(40px, …)` 压到 40px,`.14` 档 ≈ 5.6px)——这是有意的,用户明确选了 `小`。

同一轮把紧凑层的**几何值从 px 换成 rem**(以 40px 为基准:`28px → .7rem`、`30px → .75rem`、`144px → 3.6rem`…),让紧凑层随根字号缩放而不是写死。视口与安全区的 `px`(`12px`、`44px`、`48px` 之类)不换。

| --- | --- | --- |
| 资源管理 | 横屏手机双栏(窄于 560px 才堆叠),更紧凑的分类/语音行 | 必备/可选分类、语音选择、计数、体积、进度、当前导入分类、暂停、ZIP 操作、警告 |
| 设置 | 更宽的弹窗、紧凑的标签/控件行、更小的间距、自动换行的底栏 | 浏览器偏好、四档字号、诊断信息、语言、音量、键盘焦点 |
| 公告 / 关于 / 恢复 / 导入 | 可用视口高度、自动换行、固定关闭与操作区 | 链接、免责声明、选中要恢复的身份、ZIP/数据校验、草稿 |
| 对局记录 / 本局信息 | 更宽且有高度上限的弹窗、紧凑控件 | 本地记录、导入导出、全部列、回放、损坏或版本过新的警告 |
| 标题页 / 大厅 / 房间 | 紧凑卡片与操作、减少装饰性留白、输入框用真实字号、标题与徽记随根字号缩放、顶栏单行 | 语言/统计/设置/预载入口、匹配、全部座位、模式规则、邀请控件 |

管理弹窗显式传入 `Modal` 的 `utility` prop。它把请求的桌面宽度变成 `--utility-width`,好让移动端样式表改尺寸而**不被内联样式压死**;其他弹窗保持原有宽度行为。管理弹窗的头部多一个键盘可达的关闭键;原有的焦点陷阱、Escape、正文滚动与底栏操作都不变。

管理界面同时使用 `device.js` 已提供的可视视口高度 `--sp-vh`(上限 `100dvh`),软键盘因此**缩小**它们的尺寸预算,而不是把底栏操作留在键盘下面。这是静态预算契约;键盘顶起与聚焦行为仍需真机确认。

紧凑目标使用**真实盒子**,一般 `.65rem–.75rem`(40px 根字号下 26–30px);`devices.css` 那套 44px 隐形 `::before` 热区在这些作用域里被压回 `inset: 0`,因为相邻的 30px 控件之间一个 44px 热区会盖到邻居身上。文本输入框与原生 select 保留 16px 可读下限(防 iOS 聚焦放大)——上游那轮 px→rem 替换在标题登录输入框上误删过这个下限,本分支保留。字数更大的档位仍然会放大内容、可能触发滚动 —— 内容不会被截断来迎合行数预算。

## 协作房与战场

协力房的 统计/设置/公告/玩法说明 在**所有设备、协力与独立模拟一视同仁**都是真正的图标方钮(共用 `.room-tools` 类,`.75rem`,`title` 与 `aria-label` 保留原名和动作);`RoomTools` 组件因此不再接收房间类型参数。
紧凑房间在**每一个**移动端宽度都把控件、标题、邀请放在同一命名网格行里,标题永不单独换行;这一行是**单行**的 —— `.topbar__left` 与 `.connection-status` 都是 `flex-wrap: nowrap`,`.room-ping` 用 `flex: 1 1 auto` 让位,靠换行会把标题挤出它自己的网格轨道。底部选项/状态与操作同排,两条栏都改为内容撑高而不是保留桌面固定高度。密钥字符格使用自身字号,而不是小 rem 盒子套放大字形。短屏协力房整体可滚动,同时保留可见的座位区;竖屏座位行不小于卡片的最小高度(`3.5rem`)。

战场侧几乎不受影响:这一层里没有任何 `.gm__hud` / `.gm__field` / `.shopbar` / `.scard` / `.ewheel` / `.readybtn` / `.uframe` / `.dpanel` / `.chud` / `.gtop` / `.capsule` 规则,`game.css`、`game-shop.css`、`game-panels.css`、`emotes.css` 也都不读 `--utility-text`。唯一的例外是作战统计面板。

### 作战统计面板(这一层里唯一的战场内界面)

面板本体样式在 `game.css`(相对 `.gm__corner` 上浮);这一层负责它在紧凑视口里的形态:

- 给窗口一个确定高度,只把标题 / 统计范围 / 关闭键钉住,剩下整个正文可滚动,并且把**排行提到最前面**;
- `ui/combatMetricsLayout.js`(纯函数,可单测)量出角落实测高度和可视视口(`visualViewport`,含软键盘)后,把 `--combat-available-height` / `--combat-viewport-height` / `--combat-viewport-top` 写进面板;
- 角落上方不足 128px(或被浏览器 UI、软键盘遮挡)时置 `data-viewport-docked="true"`,面板改为 `position: fixed` 浮在可视视口内。

它与其它 xinhai 规则有两处**故意不一致**,不要"修回去":

1. 它的字号保留 `max(calc(…), Npx)` 下限。上游那轮 px→rem 机械替换把面板的 px 下限也一并删了,但面板的基础规则在 `game.css` 里是有下限的 —— 删掉会让紧凑层文字比基础规则**还小**,那是缩水不是紧凑。
2. 它读 `--t` 而不是 `--utility-text`:`--utility-text` 只声明在管理根节点上,面板不在其中,读它只会回退到 `--t`、顺手丢掉 game.css 的 px 下限。

`test/ui/utility-mobile.test.js` 专门钉住两点:除了 `.combat-metrics*` 之外不许有别的战场选择器进来,以及面板的声明不许读 `--utility-text`。

## 横屏

既有的全局强制横屏门槛在**所有**移动端页面继续生效,包含管理弹窗、玩法说明和作战统计。**没有任何管理界面豁免旋转提示** —— 这一层不允许出现 `rotate-hint` 或 `sp-rotatable` 规则。

横屏提示新增一个「点击进入横屏」按钮,走已有的 `fullscreen.enter()`:Android Chrome 会在全屏时锁横屏,iPhone Safari 没有元素级全屏,按钮自己隐藏。

- `test/ui/text-scale.test.js`、`test/ui/devices.test.js`、资源/语音、本机历史与既有 UI 测试保护设置、数据/聚合行为与不变的战场几何。
- `test/vite.test.js` 验证生产 CSS 的包含与顺序;`test/client-static.test.js` 验证 `devices.css` 之后只允许这一个作用域层。

静态数值预算**不模拟**字体固有宽度、CSS 布局、虚拟键盘、真机刘海或触摸命中。构建/Node 通过**不等于**浏览器或真机验证。上一层列出的 opt-in 浏览器测试已经在本机 Chrome 上跑通(844×390 / 568×320 / 四档字号,截图在 `test/e2e/out/`),但它只覆盖 Chrome 的模拟视口;**虚拟键盘、真机刘海、惯性滚动和 iOS Safari 仍需手动确认**。需要真机结论时,请同时检查源码与生产两种模式、中英两种语言、四档字号、横竖屏、长列表/长名字/大数字、安全区与嵌套弹窗,看截图并确认每个操作都真的能点到。
