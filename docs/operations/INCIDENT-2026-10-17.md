## 三、提过但否掉的

- **把 IP 从 gate 的 `bind()` 拿掉**：一道 PoW 就能被 127 台共享 6 小时，那是唯一在挡 botnet 的东西；上线瞬间所有 cookie 失效，400 人同时撞 `sp_gate_issue 6r/m`。
- **给 `/api/rooms` 开 `auth_request off`**：门户打的是 POST，服务端只允许 GET/HEAD，开了也只会 405。
- **把 `/api/ping` 加进 jail**：716 个 IP 里 339 个握过手、394 个发过 `?build=1`——CGNAT，封一个连带几百人。
- **`proxy_max_temp_file_size 0`**：4.4MB × 并发全压内存，3.9G 的机器不划算。

## 四、走错的弯路（这节才是经验）

### 命令行把数据吃掉了

| 错 | 症状 | 真相 |
|---|---|---|
| `tcpdump -q` | 抓到 0 个 SYN | `-q` 省略 `Flags [S]`，grep 全空 |
| `awk '{print $3}'` 取源 IP | 排行榜第一是 `In` | `-i any` 输出是「时间 网口 In IP 源.端口 > …」，源在 `$5` |
| `grep '"/api/ping'` | 1 万条说成 0 条 | 引号在 GET 前，不在路径前 |
| `grep 'GET /api/ping'` | 又是 0 条 | 方法是 **HEAD** |
| ssh 用了 scp 的 `-P` | host key 验证失败 | ssh 是 `-p`，scp 是 `-P` |
| 用 `=====END=====` 切段 | 名单从 55 变 108 条 | 中间没有 END，把后面两个文件也吞了 |

教训：任何「日志/抓包里是 0」的结论，先怀疑命令。每条结论要有独立来源能对上（`grep -c` 对 `fail2ban-regex` 的 Matched）。

### 先有假设，再去找证据

- **`/ws` 444 归因给 `conn_limit`**：日志字段 `req_limit=PASSED conn_limit=PASSED urt=-` 三条一起否掉了。真因是 gate 的 401→444。
- **`/api/ping` 的 339 个「真玩家」**：用「这个 IP 握过手」推的，但 **CGNAT** 让一个公网 IP 后面挂几百人。移动网络上这个推理无效。
- **「127 台只封了 55」**：按上一轮 2,073/s 时的抓包推的，重量的结果是能识别的 SYN 源全在名单里。
- **「解封后人数会回升」**：错。它们被封是**因为**被门拒，解封只是让它们重新打到 nginx 继续拿 444。

教训：结论要能写成「如果 A 成立，日志里应该出现 X」。写不出来就还是猜。

### 验证方式本身有漏洞

- `chown` 那 46 条 crit 全部集中在 `11:59:53–12:00:35` 的 42 秒，**本来就自愈了**。权限确实统一了，但不等于修掉了一个持续故障。
- 只验证「没触发」不等于验证「能触发」。`auto4` 的 0 有兩種解释，靠临时表打流量才分清。

### 改动带来的副作用

- **部署引发 10 万请求的风暴。** build tag 一变，每个开着的页面自己 reload，然后整个 `/sim/**`（约 350 个模块）从源站重下。300 人 × 350 ≈ 10 万请求压到单线程 node，load 冲到 4.77，gate 连不上 upstream，**241 个 503**。
- **本地 build 不能直接推。** 先跑 `vite build`，对比服务器 82 个资产才发现差 3 个 chunk。改成「只传源文件、在服务器上构建」。

### 排查路径

- 日志不止一个：`/var/log/nginx/access.log` 是 0 字节，游戏流量在 `/var/log/nginx/sp/stronghold.access.log`，自定义 `sp_game` 格式（带 `req_limit` / `conn_limit` / `urt`）。
- `return 444` 在浏览器里是网络错误，不是状态码。前端只能写「连续 N 次失败」。
- nginx 的 `limit_req` 跑在 `auth_request` 之前（PREACCESS vs ACCESS）——这是「被限速」和「被门拒」能在日志字段里区分的前提。
- `meter … update @set` 里 `burst` 后面必须带 `packets`，否则 `nft -c` 报 `unexpected '}'`。
- jail 停用后 `fail2ban-client -d` 看不到它，只能以文件为准。

## 五、nftables 现状（2026-10-17 16:10 普查）

输入链按优先级：

```
filter - 10  policy drop   stronghold_country   CN 段以外 new 80/443 丢
filter - 10  policy drop   sp_foreign_cap       mainland4 白名单
filter - 6   policy accept sp_syn_ban           perm4/auto4 + SYN meter
filter - 5   policy accept sp_web_syn_guard     每 IP 5 SYN/分钟
filter - 1   policy accept f2b-table            fail2ban
filter  0    policy drop   table ip/ip6 filter  (ufw)
filter + 10  policy drop   sp_lockdown          默认拒绝：lo / estab / 22 / 80,443,8080 / icmp
```

- `sp_lockdown` 的 `banned4` / `banned6` 集合**是空的**，没有任何东西往里写，等于死代码；但它的默认拒绝本身是合理的底板。
- 本机不监听 10169；公网 10169 由上层 NAT 映射到 22，所以 `sp_lockdown` 的 `tcp dport 22 accept` 够用。
- **`sp_web_syn_guard` 是每 IP 5 SYN/分钟（burst 10）**，当前集合里 245 个 IP，历史累计丢 19,051,302 包 / 1.14 GB。而实测真实玩家 SYN 峰值是 0.3/s ≈ 18/分钟——**这个阈值比真人低 3.6 倍**，集合里能看到正在游戏中的玩家 IP。见遗留问题。
