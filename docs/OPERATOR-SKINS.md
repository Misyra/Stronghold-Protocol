# 干员外观

干员调配和自选编队中的外观选择是纯展示设置，与技能、模组、持有状态、自选名额分开。现有 2D／3D 棋盘共用 Pixi Spine 人物层。（本篇合并自用户分支；目录数据见 `docs/research/08-skins.json`，已收录集合见 `data/skins-installed.json`。）

## 当前覆盖

本批核查的是游戏素材目录现有的 209 个实际 `charId`，不是明日方舟全部干员。公开游戏皮肤表与 PRTS 页面共匹配到 172 名干员、271 套时装；页面中的 `时装N名称` 与具体时装名精确对应，不用发行顺序推断 Wiki 图片编号。

目录现有 **276 套时装、174 名干员**，**已全部装进素材清单**（`data/skins-installed.json` → `data/assets.json` 的 `chars[*].skins`），包括音律联觉、登临意、「源远流长」等联动款与 NLC 联动三套（`char_1033_swire2@nlc#1`、`char_1040_blaze2@nlc#1`、`char_2025_shu@nlc#1`）。部分时装的动态资源仍缺失，界面标注“动态立绘待补 · 静态预览”。这不是全时装覆盖或全部原作特效还原。

少数时装的原资源没有背面：浊心斯卡蒂「升华」、安洁莉娜「质素访客」「夏卉 FA017」。这三套在朝上时仍使用**本套正面**，界面明确标记，不悄悄借用默认服装的背面。

## 操作与保存

- 干员调配：选中干员，在“外观”中选择时装；头像、半身图和战斗本体使用该选择。
- 自选编队：选择干员时可设置外观。外观按真实干员保存，不按 DIY 槽位保存。
- “默认外观”恢复原普通／精锐图片规则。
- “查看立绘”按需加载完整立绘。已安装动态立绘可播放原骨骼动画及原有前／背景，支持暂停、动作切换、静态切换。
- `prefers-reduced-motion` 时动态预览默认暂停；隐藏页面停止动画，关闭预览销毁自己的渲染器并释放资源引用。不会在全部卡片中同时播放动态立绘。
- 设置保存于浏览器 `sp.pref.skins`，通过“导出全部外观／导入外观”在浏览器间迁移，不是账号跨设备数据库同步。本地键是**棋子 id**（`chess_char_1_01_a`，干员调配的花名册、自选槽位、商店立绘都按它存），发到服务器时才由 `ui/skins.js skinChoicesOf` 翻成 `{[charId]: skinId}`——线上一律按**干员**，一个条目覆盖同名的普通棋、精锐棋和自选了这名干员的自选槽。
- 既有技能／模组、持有与自选导入导出格式不变；外观单独使用 `{kind: 'stronghold.skins', v: 1, choices}`。
- 本局确认阶段 `INFO_CHECK` 结束后锁定外观；之后的修改保存给下一局，不中途替换单位。

## 同步与安全边界

`room.skins {choices}` 为 `{[actualCharId]: admittedSkinId}`，只接受共享目录中绑定到该干员的标识，不接受任意 URL、未知标识、跨干员借用或原型属性键。校验就是目录本身（`shared/skins.js isSkinChoices`）：一条不合规就整份 `BAD_MSG`、一条都不存，没有第二份需要维护的白名单。沿用既有有界消息、重型消息限流及连接顺序。

Session／座位／PlayerState／集群 assignment 独立复制、冻结选择。`m.private.skins` 只发给本人；队友侦察、旁观、Boss 搭档、战斗及结算只携带可见单位自己的 `skinId`，不公开完整个人设置。

皮肤不替换 `charId`、棋子 ID、`spine`／语音身份，不写入共享战斗 def，不改变技能、模组、属性、攻击命中时序、RNG 或结算。未持有干员的替补使用替补实际身份；不能把被替换干员的皮肤套在替补上。不同玩家的同款干员各用自己的选择。

骨骼／图片加载失败时回退默认外观，动态预览失败时回退静态立绘，不影响战斗。召唤物时装、原作独立弹道／技能特效、专属语音不由此功能自动支持。动态立绘中的原骨骼效果与战斗程序化特效是两个不同的系统。

## 素材导入

素材来自公开 PRTS 图片信息接口和经过验证的 `/spine38/` 资源，运行时不热链 Wiki。旧 `/spine/` 可能为 3.5 binary，本项目解析工具要求实际兼容的 3.8 骨骼；每套校验 atlas 页面、PNG 尺寸、骨骼版本／附件及动画。Wiki 图片按其 size／SHA1 校验，再记录 SHA256。动态骨骼、纹理与配置存在并可解析才标为可用动态立绘；不能把游戏表的动态标记当作资源已安装。

展示副本清除骨骼头中仅供编辑器使用的 `imagesPath`／`audioPath`，不改附件、骨骼和动画主体字节；原始下载留在隔离来源库存，并分别记录原始／展示副本哈希。现有琴柳「夏卉 FA317」正背骨骼已转换为独立的 `.display.skel`，主体逐字节及解析结果一致，原件不覆盖、不列入发行素材清单。完整打包仍执行个人路径扫描，不豁免原始美术文件。

导入工具本身不入库（美术、原始来源、下载库存与缓存不进 Git）：素材由维护者的本地管线产出到 `public/assets/` 与 `data/` 索引；仓库内的配套工具是 `tools/install-skins.mjs`（管理 `data/skins-installed.json` 的已收录集合，`list/add/remove/add-char`）与 `tools/fetch-assets.mjs`（重建默认素材时保留已收录且文件完整的时装，并将其文件纳入清单与 prune 引用；不为缺失素材发出坏 URL）。新游戏版本、私有素材清单与公开静态文件必须作为配套材料准备；本地素材不进入 Git，也不代表已上传 provider 或部署。

原始立绘、模型、音频等归相关游戏权利方所有。PRTS Wiki 的文字许可不能作为游戏素材再分发的独立授权。

## 验收边界

功能在用户分支以本地真实 HTTP／WS、实际 combat Worker、双人浏览器与真实私有集群 RPC／WS 验证展示同步和重连；独立数值回归比较默认／皮肤的 snapshot、结果、RNG 与 def。浏览器验收使用 Chrome 软件 WebGL 与手机模拟，不是实体手机或硬件 GPU 性能测试。

动态立绘实测耀骑士临光「复现荣光」：原分层、播放时画面变化、暂停画面稳定、动作／静态切换、手机减少动态默认暂停、关闭销毁渲染器。泥岩双人不同外观、正背模型、浊心斯卡蒂仅正面、队友查看、外部旁观与战斗重连也已实测，旁观者不收到被观看玩家的私有配置。

另以精确的本地 404 夹具验证：动态骨骼缺失回退静态立绘，时装图片缺失回退默认半身像，时装战斗骨骼缺失仍显示实际默认 Spine 模型、保留选择。

移植后回归：合并分支的皮肤/DIY/调配测试（`test/skins-diy.test.js`、`test/ui/skin-picker.test.js`、`test/ui/diy-ui.test.js`、`test/ui/loadout*.test.js` 等）全绿，并以真实浏览器验证调配/自选编队的外观选择、立绘四选一与战斗模型联动。上述并非逐套动画人工视觉验收、实体手机测试或与原作逐像素一致性保证。
