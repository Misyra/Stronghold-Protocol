每站补记时间、提交、探针版本、实际配置路径、备份位置和验证结果。门户独立发布；游戏仓库的 ops 由门户同步脚本生成，禁止在两边分别维护。先检查同步，再替换探针源码，保留凭据与历史库。

游戏更新继续沿用已有保存 → 重启 → 自动重连恢复流程，不等待对局结束。上线前确认持久化配置及重启前后的同一状态目录，停止时让最终保存完成。回退保留数据库/状态文件，先核对版本兼容性。

nginx 使用仓库缓存示例和 `scripts/nginx-log-format.conf.example`，按主机现有 http/server 层级合并，先配置检查再 reload。先记录旧配置和回滚文件；本地 Windows 未执行 nginx 配置检查。不得直接把带版本目录剥前缀并永久缓存当前字节，动态转换、旧 tag 校验和 sim 私有文件保护仍由现有链路负责。

玩家版本轮询改用 `/healthz?build=1`，仅返回版本号；监控探针继续请求完整 `/healthz`。隐藏标签暂停版本请求，恢复前台立即检查。旧服务忽略 query 并返回完整响应时仍可兼容。确认代理没有忽略 query 而混用这两个响应。

上线观察至少覆盖一个晚高峰，对比成功率、排队/延迟、回源、传输正文量和新失败；不要将共享缓存减少的回源量等同于客户端出网减少，也不要相加报告中的重叠收益。

## 客户端网络证据

Windows 本机运行，例如：

```powershell
./scripts/network-probe.ps1 -Url 'https://你的站点/api/ping' -IntervalSeconds 30 -Count 120 -OutputFile "$env:TEMP/sp-network.jsonl"
```

使用实际站点地址。每条记录为 UTC 时间和新连接 HEAD 请求，最多等待 20 秒；Ctrl-C 可停止。DNS、connect、TLS、首字节时间均为从开始累计，分析阶段耗时时需相减；HTTP 时 TLS 为 0。curlExit 非 0 表示传输失败，HTTP 状态 000 与缺失不是服务端成功。探针不跟随重定向，不复用浏览器 HTTP/2 连接，因此只能作为独立链路证据，不能单凭一次成功排除浏览器故障。对照服务器同一 UTC 时段的请求计时与云事件再判断。

输出可能含访问时间与网络故障信息，留在本机，不加入仓库；不填写带凭据或敏感查询参数的地址。
