# WebSocket 增量本地对照测试（2026-10-09）

在本分支已移植的增量实现（666fc606）上执行，压测工具改编自 xinhai 2abc60f0。10 轮正式测试全部通过；另有 40 连接全量／增量启动检查。

2000 连接、500 个四人房间下，两轮平均值显示：1Hz 公共广播时实际总下行流量降低 **64.1%**、状态帧流量降低 **84.9%**、服务端 CPU 用时降低 **30.1%**；4Hz 时分别降低 **78.8% / 86.3% / 47.3%**。增量模式的服务端 RSS 更高，约 880–1061 MiB，全量为 580–634 MiB。RSS 为结束时单点读数，未强制 GC，包含缓存和临时对象，不能直接视为基线的净内存成本。

1Hz 的操作状态到达 P95：全量 123–138ms，增量 16.26–16.48ms。4Hz 的 P95：全量 216–631ms，增量 110–131ms；高频延迟存在明显调度波动，保留每轮结果，不以单次最好值作承诺。

## 环境与负载

- Windows，AMD Ryzen 7 7840H，16 个逻辑 CPU，23.2 GiB 内存；Node v24.19.0，ws 8.22.0。
- 客户端、服务端独立 Node 进程，同机回环网络。服务端固定 CPU 0–7，客户端固定 CPU 8–15；UV_THREADPOOL_SIZE=4。压测逐轮串行，无 TLS、代理或线上网络。
- 使用本仓库对局引擎、seed=7、四名玩家，经测试辅助脚本推进到第 6 回合 PREP。原始对局四人的阵容数量为 8／8／8／9；公共视图 5112 字节，私人视图取第一名玩家的 8 干员阵容（5061 字节），包含实际商店和手牌。各连接分别克隆该私人模板并改写身份。推进样本时使用替代战斗，不测真实战斗计算。
- 测量期创建真实四人大厅，通过生产 broadcastRoom / sendSession 和协商后的 WebSocket 发送这些视图。周期改变公共 ready、时间戳和私人 funds 等字段；并不创建 500 场运行中的真实对局。
- 公共状态每秒 1 或 4 次，私人背景状态频率为公共的四分之一。每连接每 4 秒错峰发送 ping 和 room.ready，私人操作状态在确认消息前推送。P95 从发送 room.ready 到收到对应私人状态计算，解码使用生产 StateReceiver，不包含浏览器渲染。
- 开启生产 permessage-deflate，阈值 1024 字节。全量消息会压缩，增量补丁通常低于阈值；测量实际压缩后的 WebSocket 帧和 socket 字节，不以原始 JSON 大小推算带宽。
- 400 连接测量 12 秒；2000 连接每轮测量 20 秒。2000 连接的 1Hz、4Hz 均按 full → delta → delta → full 顺序执行。建连和初始完整同步在测量期之前；结束时等待已产生状态投递完成。探测截止时点会带来少量帧数差异，未筛选结果。
- CPU 为服务端所有线程累计 CPU 秒数，非墙钟耗时；RSS 只统计服务端进程。背景状态的时间戳来自同机单调时钟，客户端与服务端时钟可比较。

## 正确性校验

10 轮均无操作失败、解码失败或状态／确认顺序错误，结束时发送缓冲为零。逐轮核对生成帧数、收到帧数、原始状态字节、压缩后的 payload、帧头、socket 实际收发字节及压缩次数，8 项核账全部一致。

4Hz 第二轮全量与增量另行核对所有 2000 个客户端的最终公共及私人完整状态：每模式 4000 份，合计 8000 份，按排序后的 JSON 做 SHA-256 比对，差异为零。完整终态校验发生在服务端 CPU 计时结束之后。早期轮次未增加终态哈希，不能将此项校验归到全部 10 轮；现有完整脚本化对局测试另有逐帧状态相等断言。

实际测量的是传输路径在小幅状态更新下的收益，未包含真实对局调度、AI、战斗模拟、Redis、浏览器渲染、TLS 和公网延迟，不代表能承载 2000 名真实对局玩家。大幅阵容变化、重连及全量回退的收益也不能直接套用本表。

## 复现

工具：tools/bench-state-delta.mjs。以下命令在仓库根目录执行，默认不固定 CPU；本次数据另加 --server-cpus 0,1,2,3,4,5,6,7 --client-cpus 8,9,10,11,12,13,14,15，两组标号按本机调整。Windows 使用原生进程亲和性；其他平台启用此选项需要 Python psutil。

```powershell
node tools/bench-state-delta.mjs --generate-samples --samples .cache/ws-local-samples.json
node tools/bench-state-delta.mjs --variant full --samples .cache/ws-local-samples.json --sockets 2000 --seconds 20 --hz 1 > .cache/ws-local-full.json
node tools/bench-state-delta.mjs --variant delta --samples .cache/ws-local-samples.json --sockets 2000 --seconds 20 --hz 1 > .cache/ws-local-delta.json
```

高频对照将两条测试命令的 --hz 改为 4。建议交换顺序重复；若帧计数、终态哈希、操作顺序或缓冲校验失败，工具以非零状态退出。脚本使用 ws 8.x 的私有 sender / deflate 接口观测真实帧，升级 ws 后应先确认核账仍通过。

本次完整 JSON 原始结果保留在本地 .cache/ws-local-{400|2000}-{1|4}-{full|delta}-r{轮次}.json，样本为 .cache/ws-local-samples.json；缓存不提交入库。
