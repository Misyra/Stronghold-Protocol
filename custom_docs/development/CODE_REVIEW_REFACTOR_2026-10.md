# 2026-10 代码审查整改记录

依据 [CODE_REVIEW_2026-10.md](CODE_REVIEW_2026-10.md)。本记录描述实际改动，不修改原审查报告。

## 本机统计的决定

按用户要求，采用上游 `ui/stats.js` 的记录模型与 `screens/stats.js` 的统计界面。

- `m.result` 只调用一次上游 `recordResult`；中途退出继续使用上游 `recordQuit`。
- 删除自写历史弹窗、入口、样式、保存状态组件，以及 `resultPlayerCard.js` 影子副本。结算卡片恢复使用上游 `result.js` 原件；统计页的回看也使用同一个 `ResultView`。
- 结算页的“对局记录”直接打开上游统计页的历史页签。点击事件对象不会被误当成页签名。
- 首次打开统计页时，将旧 IndexedDB 记录合并到上游统计存储，按上游内容 ID 去重。异步读取完成后重新读取当前统计，保留迁移期间到达的新结算。
- 旧数据库保留作恢复副本，迁移成功才写完成标记；写入失败可重试。空旧库不会覆盖较新版本统计，也不会刷新掉损坏数据的备份提示。
- 旧 JSON 导出格式继续可从上游统计页导入。`history/legacyBackup.js` 只解析旧备份，`history/legacyStorage.js` 只以 readonly 事务读旧库并立即关闭连接；删除原记录生成、写库、删除、导出接口。新浏览器不会因迁移创建旧库。

## 保留的边界

- 审核采用有界匹配，未改成任意子序列、全量简繁/同形转换或“软命中后复核”系统。它覆盖新增回归中的插入变体，不代表能识别所有规避方式；现有正常昵称、词表精确命中和数字边界约束继续成立。
- 元数据版本降低大型结算与回放的重复处理成本；会话和房间的小字段仍需比较，成本仍会随房间数量增长。没有把小规模基准当成线上容量结论。
- 出站泵与 heartbeat 泵的调度语义不同，保留各自的公平性/完成语义，只集中预算常量。
- R2 清单没有可靠的本地文件变更戳，因此未凭旧 hash 直接跳过文件校验。使用并发流式校验，避免发布陈旧字节。
- 未机械删除所有通用 CSS 回退声明或测试兼容导出；移动端的局部字号、16px 输入下限、作战统计字号下限及横屏门槛保留。
- 固定赠品库存采用上游 0.2.5 模型；官方场景文件仍不入库。
