# 管理界面的移动端密度(移植自 xinhai-ai/Stronghold-Protocol)

本分支把**战场**和**非战场管理界面**分开处理:`.gm__hud`、商店、HUD 几何、聊天尺寸、局内统计和详情卡都不动,只有管理界面走这一层。
`public/css/utility-mobile.css` 在 `devices.css` **之后**加载(源码 `public/index.html`、`public/dev/*.html` 和 Vite 构建都是),除此之外没有别的样式表排它后面。

## 作用域与密度

规则在 **1000 CSS px 宽以下**或 **600 CSS px 高以下**生效。桌面布局不变,`html` 的全局 `rem` 也不变。
共享排版用 `var(--utility-text, var(--t))`;只有管理容器自己定义可读下限。

`--utility-text` **必须由每个管理根节点自己声明**,因为 `UiHosts` / `GuideHost` / `LoadoutHost` / `StatsHost` / `ResourceManagerHost` 都是 `.app-root` 的子节点、**不是屏幕的子节点** —— 从标题页或对局中打开的资源管理弹窗继承不到大厅上的变量。
这个变量**只允许出现在 `font-size` 上**,不能用来算宽度、高度或战场定位;`test/ui/utility-mobile.test.js` 会扫描该层每一条声明。

| 界面 | 移动端的调整 | 保持不变的部分 |
| --- | --- | --- |
| 资源管理 | 横屏手机双栏(窄于 560px 才堆叠),更紧凑的分类/语音行 | 必备/可选分类、语音选择、计数、体积、进度、当前导入分类、暂停、ZIP 操作、警告 |
| 设置 | 更宽的弹窗、紧凑的标签/控件行、更小的间距、自动换行的底栏 | 浏览器偏好、四档字号、诊断信息、语言、音量、键盘焦点 |
| 公告 / 关于 / 恢复 / 导入 | 可用视口高度、自动换行、固定关闭与操作区 | 链接、免责声明、选中要恢复的身份、ZIP/数据校验、草稿 |
| 对局记录 / 本局信息 | 更宽且有高度上限的弹窗、紧凑控件 | 本地记录、导入导出、全部列、回放、损坏或版本过新的警告 |
| 标题页 / 大厅 / 房间 | 紧凑卡片与操作、减少装饰性留白、输入框用真实字号 | 语言/统计/设置/预载入口、匹配、全部座位、模式规则、邀请控件 |
| 干员调配 / 干员持有 / 自选编队 | 更小的快捷选择按钮、紧凑筛选、响应式网格 | 全部技能/模组/潜能/练度列、盟约标签、搜索、滚动、原有列表↔详情流程 |
| 本机历史统计 | 紧凑的头部/卡片/表格、全宽、警告仍在 | 仅本机记录、导入导出、全部列、回放、损坏或版本过新的警告 |
| 玩法说明 | 动态高度与安全区预算、可滚动的章节与页码控件、文字回退 | 全部页面、16:9 图片、关闭/翻页、键盘快捷键 |

管理弹窗显式传入 `Modal` 的 `utility` prop。它把请求的桌面宽度变成 `--utility-width`,好让移动端样式表改尺寸而**不被内联样式压死**;其他弹窗保持原有宽度行为。管理弹窗的头部多一个键盘可达的关闭键;原有的焦点陷阱、Escape、正文滚动与底栏操作都不变。

管理界面同时使用 `device.js` 已提供的可视视口高度 `--sp-vh`(上限 `100dvh`),软键盘因此**缩小**它们的尺寸预算,而不是把底栏操作留在键盘下面。这是静态预算契约;键盘顶起与聚焦行为仍需真机确认。

紧凑目标使用**真实盒子**,一般 26–30px;`devices.css` 那套 44px 隐形 `::before` 热区在这些作用域里被压回 `inset: 0`,因为相邻的 30px 控件之间一个 44px 热区会盖到邻居身上。文本输入框与原生 select 保留 16px 可读下限(防 iOS 聚焦放大)。字数更大的档位仍然会放大内容、可能触发滚动 —— 内容不会被截断来迎合行数预算。

**下限的代价(有意接受)**:手机上 `rem` 被钳在 40px,设计本身的正文是 7.2px,因此在管理界面里 `小`(40px)与 `中`(64px)都会落在 `max(var(--t), 64px)` 这条下限上、看起来一样大;`大` 与 `特大` 仍然明显更大。战场、商店、HUD、聊天与详情卡读的是原始 `--t`,四档区分完全不变。若要把四档在管理界面里也分开,把下限改成 40 到 64 之间的值即可 —— 但那是偏离上游的一个决定。

## 协作房与战场

协力房的 统计/设置/公告/玩法说明 在**所有设备**都是真正的图标方钮(共用 `.room-tools` 类,`title` 与 `aria-label` 保留原名和动作);独立模拟的入口保留文字。
紧凑房间在**每一个**移动端宽度都把控件、标题、邀请放在同一命名网格行里,标题永不单独换行;底部选项/状态与操作同排,两条栏都改为内容撑高而不是保留桌面固定高度。密钥字符格使用自身字号,而不是小 rem 盒子套放大字形。短屏协力房整体可滚动,同时保留可见的座位区;竖屏座位行不小于卡片的最小高度。

战场侧完全不受影响:这一层里没有任何 `.gm__hud` / `.gm__field` / `.shopbar` / `.scard` / `.ewheel` / `.readybtn` / `.uframe` / `.dpanel` / `.chud` 规则,`game.css`、`game-shop.css`、`game-panels.css`、`emotes.css` 也都不读 `--utility-text`。

## 横屏

既有的全局强制横屏门槛在**所有**移动端页面继续生效,包含管理弹窗、玩法说明和作战统计。**没有任何管理界面豁免旋转提示** —— 这一层不允许出现 `rotate-hint` 或 `sp-rotatable` 规则。

横屏提示新增一个「点击进入横屏」按钮,走已有的 `fullscreen.enter()`:Android Chrome 会在全屏时锁横屏,iPhone Safari 没有元素级全屏,按钮自己隐藏。

## 验证

- `test/ui/utility-mobile.test.js` 检查变量契约(只能用于字号、`--t` 仍只由 `theme.css` 定义)、样式表加载顺序、opt-in 边界(哪些弹窗进这一层、哪些战斗内弹窗不进)、内容保留、真实命中盒、横屏门槛,并在 320×568、390×844、640×360、844×390、915×412、1000×600 六种视口加合成安全区上求值显式宽度/高度预算。
- `test/ui/room-mobile.test.js` 检查四个房间工具的成分与可访问名,并在 `components.css → room.css → utility-mobile.css` 三层真实层叠上验证命名网格区,包含 760/761 两侧、竖屏自动行和桌面固定高度不被改动。
- `test/ui/text-scale.test.js`、`test/ui/devices.test.js`、资源/语音、本机历史与既有 UI 测试保护设置、数据/聚合行为与不变的战场几何。
- `test/vite.test.js` 验证生产 CSS 的包含与顺序;`test/client-static.test.js` 验证 `devices.css` 之后只允许这一个作用域层。
- `test/ui/utility-mobile.e2e.test.js`(**opt-in,需要 Chrome**:`SP_E2E=1 CHROME_PATH=… node --test test/ui/utility-mobile.e2e.test.js`)在真实 Chrome 上跑源码客户端,覆盖 844×390、568×320 小横屏、以及 `中`/`特大` 两档字号:设置弹窗必须落在可视视口内、正文可滚动、28 个控件**逐个滚动到位后**中心点真的能点到(44px 隐形热区不得压住邻居)、按钮 ≥24px、正文 ≥11px、输入框 ≥16px;大厅/本机历史统计不横向溢出;协力房四个工具 30px 可点、保留可访问名、标题与控件和邀请同一行;竖屏旋转门槛覆盖所有管理界面。它不需要构建(直接服务源码),打包后的那份由 `test/vite.test.js` 负责。
- opt-in 的设备浏览器测试保留横屏检查。

静态数值预算**不模拟**字体固有宽度、CSS 布局、虚拟键盘、真机刘海或触摸命中。构建/Node 通过**不等于**浏览器或真机验证。上一层列出的 opt-in 浏览器测试已经在本机 Chrome 上跑通(844×390 / 568×320 / 四档字号,截图在 `test/e2e/out/`),但它只覆盖 Chrome 的模拟视口;**虚拟键盘、真机刘海、惯性滚动和 iOS Safari 仍需手动确认**。需要真机结论时,请同时检查源码与生产两种模式、中英两种语言、四档字号、横竖屏、长列表/长名字/大数字、安全区与嵌套弹窗,看截图并确认每个操作都真的能点到。

**部署需要重新构建前端并更新带哈希的资源与 HTML;只重启旧构建不会应用这一层。**
