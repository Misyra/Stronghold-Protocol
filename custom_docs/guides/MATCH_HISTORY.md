# 本机统计与对局记录

本版本统一采用上游的本机统计模型。首页、大厅与房间的「统计」入口可查看总览、策略、战斗累计和对局记录；结算页的「对局记录」直接打开同一界面的历史页签。

## 保存与回看

- 收到结算后自动保存，中途退出也会留下记录。至少完成过自己的第一场战斗后退出才计入统计；更早退出仅列入历史。
- 最多保存 1000 局，最近 30 局保留完整结算详情。更早记录会压缩为本人的统计摘要，不能重新打开完整结算。存储预算不足时会进一步缩减数量。
- 完整记录可回看队员、阵容、装备、盟约、称号与结算统计；这是结算回看，不是逐帧战斗录像。
- 同一结算重复推送会按上游内容 ID 去重。观战者不会获得个人战绩。
- 当前记录保存在浏览器 localStorage 的 `sp.pref.stats` 中；不上传服务器，不保存连接令牌。

## 旧记录兼容

首次打开统计界面时，会读取旧 IndexedDB 数据库 `stronghold-match-history`，合并到现有统计，并跳过已经记录的结算。迁移成功后写完成标记；写入失败可再次打开重试。旧数据库保留作恢复副本，新对局只写上游统计模型。

旧格式 `stronghold-match-history` JSON 备份仍可从统计页导入，转换后按同样的去重、数量和存储预算处理。超出大小限制或结构无效的备份会被拒绝。

## 数据管理

- 「导出」下载上游 `local-stats` 格式的 JSON 备份。
- 「导入」合并备份与当前记录；文件上限为 8,000,000 字节，重复记录跳过。
- 「清空」需要页面内确认。较新版本的数据不会被旧客户端覆盖，损坏数据会另存为本机备份并提示。
- 浏览器、设备或域名不同，记录分别保存；清除网站数据或关闭无痕窗口可能删除记录。建议定期导出备份。
- 过去没有被浏览器保存的对局无法补回。禁用本机存储或额度不足时，正常对局仍可继续，但记录可能无法持久保存。

## 验证

`npm test` 包含上游统计模型、旧格式校验和迁移回归。`test/ui/stats.e2e.test.js` 覆盖统计页面、退出计数、结算去重、导入导出与清空；`test/history/browser.e2e.test.js` 覆盖真实 IndexedDB 一次性迁移及重载保留。

Windows PowerShell 的迁移浏览器检查：

```powershell
$env:HISTORY_E2E='1'
$env:CHROME_PATH='C:/Program Files/Google/Chrome/Application/chrome.exe'
node --import ./test/helpers/test-setup.js --test test/history/browser.e2e.test.js
```

统计页面与移动端检查使用 `SP_E2E=1`，也需设置可用的 `CHROME_PATH`。浏览器测试使用独立临时端口，不修改线上数据。
